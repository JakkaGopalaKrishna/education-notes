## simple Description:

# 1. What is Software? Types of Software’s?

Software is a collection of programs, instructions, and data used to perform tasks on a computer.

## Types of Software

### System Software

Software that manages hardware and provides a platform for applications.

### Application Software

Software designed for end users to perform specific tasks.

---

# 2. What is Software Testing?

Software Testing is the process of verifying and validating software to identify defects and ensure it meets requirements.

---

# 3. What is Software Quality?

Software Quality is the degree to which software meets specified requirements and user expectations.

---

# 4. Project Vs Product

### Project

Software developed for a specific client based on custom requirements.

### Product

Software developed for multiple users and released to the market.

---

# 5. Why do we need Testing?

Testing is needed to identify defects, improve quality, and ensure the application works correctly.

---

# 6. Error, Bug & Failure

### Error

A human mistake made during software development.

### Bug/Defect

A flaw in the software caused by an error.

### Failure

Inability of the software to perform expected functionality during execution.

---

# 7. Why the software has bugs?

Software has bugs because of human mistakes, requirement misunderstandings, complex logic, and environment issues.

---

# 8. Software Development Life Cycle (SDLC)

SDLC is a structured process used to develop software through different phases.

---

# 9. Waterfall Model

A sequential SDLC model where each phase is completed before the next phase starts.

---

# 10. Spiral Model

An SDLC model that combines iterative development with risk analysis.

---

# 11. V-Model

An SDLC model where testing activities are planned parallel to development activities.

---

# 12. Static Testing & Dynamic Testing

### Static Testing

Testing performed without executing the software code.

### Dynamic Testing

Testing performed by executing the software code.

---

# 13. Verification & Validation

### Verification

Process of checking whether the product is developed correctly.

### Validation

Process of checking whether the correct product is developed.

---

# 14. White Box & Black Box Testing Methods

### White Box Testing

Testing performed with knowledge of internal code and logic.

### Black Box Testing

Testing performed without knowledge of internal code and logic.

---

# 15. Static Testing & Dynamic Testing

### Static Testing

Testing done without code execution.

### Dynamic Testing

Testing done by executing the application.

---

# 16. Review, Walkthrough & Inspection

### Review

Evaluation of software documents or code to identify defects.

### Walkthrough

A review process where the author explains the document or code step-by-step.

### Inspection

A formal review process used to identify defects systematically.

---

# 17. QA & QC & QE

### QA (Quality Assurance)

Process-oriented activity focused on defect prevention.

### QC (Quality Control)

Product-oriented activity focused on defect detection.

### QE (Quality Engineering)

Engineering approach focused on continuous quality improvement using automation and tools.

---

# 18. Levels of Software Testing

Different stages of testing performed during software development.

---

# 19. Unit Testing

Testing individual units or components of software separately.

---

# 20. Integration Testing

Testing interaction between combined modules or components.

---

# 21. System Testing

Testing the complete integrated application as a whole.

---

# 22. UAT Testing

Testing performed by end users or clients to validate business requirements.

---

# 23. System Testing

Testing the entire software system to verify complete functionality.

---

# 24. GUI Testing

Testing graphical user interface elements and visual behavior of the application.

---

# 25. GUI Checklist

A list of UI-related points used to verify graphical user interface behavior and appearance.

---

# 26. Usability Testing

Testing performed to evaluate user friendliness and ease of use of an application.

---

# 27. Functional Testing

Testing performed to verify software functionality against requirements.

---

# 28. Object Properties Testing

Testing performed to verify properties and behavior of UI objects/components.

---

# 29. Database Testing

Testing performed to verify database integrity, data validity, and backend operations.

---

# 30. Error Handling Testing

Testing performed to verify application behavior during invalid or unexpected conditions.

---

# 31. Calculation & Manipulation Testing

Testing performed to verify calculations and data manipulation operations.

---

# 32. Links Existence & Links Execution

### Links Existence Testing

Testing performed to verify whether required links are present.

### Links Execution Testing

Testing performed to verify whether links navigate correctly.

---

# 33. Cookies & Sessions

### Cookies

Small text files stored in browser to maintain user information.

### Sessions

Server-side mechanism used to store user information temporarily.

---

# 34. Non Functional Testing

Testing performed to verify quality attributes like performance, security, and usability.

---

# 35. Performance Testing

Testing performed to evaluate speed, stability, and scalability under workload.

---

# 36. Security Testing

Testing performed to identify vulnerabilities and ensure application security.

---

# 37. Recovery Testing

Testing performed to verify system recovery after crashes or failures.

---

# 38. Compatibility Testing

Testing performed to verify application behavior across different environments.

---

# 39. Installation Testing

Testing performed to verify software installation and uninstallation process.

---

# 40. Sanitation/Garbage Testing

Testing performed using invalid or random input to verify application stability.

---

# 41. Difference Between Functional and Non Functional Testing

### Functional Testing

Testing that verifies application functionality.

### Non Functional Testing

Testing that verifies performance and quality attributes.

---

# 42. Regression Testing

Testing performed to ensure existing functionality works correctly after changes.

---

# 43. Re-testing

Testing performed to verify whether a specific defect is fixed.

---

# 44. Regression vs Re-testing

### Regression Testing

Testing existing functionality after changes.

### Re-testing

Testing specific defect fixes.

---

# 45. Smoke Testing and Sanity Testing

### Smoke Testing

Basic testing performed to verify build stability.

### Sanity Testing

Focused testing performed after small changes or bug fixes.

---

# 46. Exploratory Testing

Testing where testers explore the application without predefined test cases.

---

# 47. Adhoc Testing

Random testing performed without planning or documentation.

---

# 48. Monkey Testing

Random testing performed to check system stability and crash handling.

---

# 49. Difference Between Exploratory vs Adhoc vs Monkey Testing

### Exploratory Testing

Semi-structured testing with simultaneous learning and execution.

### Adhoc Testing

Unstructured random testing without documentation.

### Monkey Testing

Completely random testing focused on crashes and stability.

---

# 50. Positive and Negative Testing

### Positive Testing

Testing performed using valid input data.

### Negative Testing

Testing performed using invalid input data.

---

# 51. Positive vs Negative Test Cases

### Positive Test Cases

Test cases created using valid inputs and expected behavior.

### Negative Test Cases

Test cases created using invalid inputs and error scenarios.

---

# 52. End to End Testing

Testing performed to validate complete business workflows from start to finish.

---

# 53. Localization and Globalization/Internalization Testing

### Localization Testing

Testing performed for a specific language or regional setting.

### Globalization/Internationalization Testing

Testing performed to verify global adaptability of the application.

---

# 54. Test Case Design Techniques

Methods used to create effective test cases.

## Equivalence Class Partitioning

Technique that divides input data into valid and invalid groups.

## Boundary Value Analysis (BVA)

Technique that tests values at boundary limits.

## Decision Table

Technique used to test combinations of conditions and actions.

## State Transition

Technique used to verify behavior changes between different states.

## Error Guessing

Experience-based technique used to predict possible defects.

---

# 55. Software Testing Life Cycle (STLC)

A structured process followed by the testing team during software testing.

## Test Design/Development

Phase where test cases and test data are prepared.

## Test Execution

Phase where test cases are executed.

## Defect Reporting & Tracking

Phase where defects are logged and tracked.

## Test Closure

Final phase where testing activities are completed and reviewed.

---

# 56. Test Plan

A document that describes testing scope, objectives, strategy, resources, and schedule.

---

# 57. Use Case Vs Test Scenario Vs Test Case

### Use Case

Description of user interaction with the system.

### Test Scenario

High-level functionality to be tested.

### Test Case

Detailed document containing steps, input, and expected results.

---

# 58. Test Case Template

A predefined format used to create structured test cases.

---

# 59. RTM (Requirement Traceability Matrix)

A document used to map requirements with corresponding test cases.

---

# 60. Test Environment Setup & Test Execution

### Test Environment Setup

Process of preparing hardware, software, and tools required for testing.

### Test Execution

Process of running test cases and validating actual results.

---

# 61. Defects/Bugs

Flaws or issues in software that cause incorrect behavior.

---

# 62. Contents in Defect Report

Details included in a defect report used for tracking and fixing defects.

---

# 63. Defect Classification (Severity & Priority)

### Severity

Impact level of a defect on the application.

### Priority

Urgency level for fixing a defect.

---

# 64. Defect/Bug Life Cycle

The sequence of stages through which a defect moves from identification to closure.

---

# 65. Test Closure/When To Stop Testing?

### Test Closure

Final phase where testing activities are completed and documented.

### When To Stop Testing

Testing stops when exit criteria are met and major defects are resolved.

---

# 66. Software Testing Metrics

Measurable values used to evaluate testing effectiveness and software quality.

---

# 67. QA/Testing Activities

### QA Activities

Process-oriented activities performed to ensure quality standards.

### Testing Activities

Execution-oriented activities performed to identify defects.

---

# 68. Principles of Software Testing

Fundamental guidelines that help testers perform effective software testing.
