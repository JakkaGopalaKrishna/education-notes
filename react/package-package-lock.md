# Understanding package.json and package-lock.json

This guide explains how `package.json` and `package-lock.json` work in npm, focusing on dependency management, versioning, and ensuring consistent builds.

---

## 📌 Key Takeaways

### 📦 package.json
- Defines project metadata
- Contains scripts for running and building the project
- Lists dependencies
- Uses **Semantic Versioning** to specify dependency versions

---

### 🔢 Semantic Versioning
Version format: `Major.Minor.Patch`

- **Major** → Breaking changes  
- **Minor** → New features (backward-compatible)  
- **Patch** → Bug fixes  

---

### ⚙️ Versioning Symbols

#### ^ Carat (5:52)
- Allows updates to **minor** and **patch** versions  
- Example: `^1.2.3` → can update to `1.x.x` (but not `2.0.0`)

#### ~ Tilde (8:09)
- Allows updates to **patch** versions only  
- Example: `~1.2.3` → can update to `1.2.x` (but not `1.3.0`)

#### Fixed Version (9:18)
- Exact version is installed  
- Example: `1.2.3` → no automatic updates  

---

### 🔒 package-lock.json
- Automatically generated by npm  
- Stores a **snapshot of the entire dependency tree**  
- Ensures all developers install the exact same versions, including sub-dependencies  
- Critical for **reproducible builds**

---

## 🚀 Best Practices for Installations

### npm install
- Installs dependencies based on `package.json`
- Uses `package-lock.json` if available
- May update the lock file if inconsistencies are found

---

### npm ci 
- Recommended for **CI/CD environments**
- Installs strictly from `package-lock.json`
- Fails if there is any mismatch with `package.json`
- Ensures **consistent and reliable builds**

---

## ✅ Conclusion

- Always commit `package-lock.json` to your repository  
- Ensures stability and consistency across environments  
- Prevents unexpected dependency changes
